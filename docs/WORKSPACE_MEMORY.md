## 目录归属与空间规则

- `data/`负责稳定调用，`docs/`负责现行入口、知识和进度，`tools/`负责可复用工具。
- `循环稳定性数据库_v0.*`为版本化科学交付，旧文献批次目录为出处和审查历史。原位保留，通过索引区分用途；不为根目录好看而移动并破坏证据路径。
- `.venv`是可用依赖环境，`.git`和LFS对象支撑版本与同步；它们有明确用途，不能仅因大就删除。不在本任务清理系统、共享运行时或外部原文库。
- 临时工作可用已忽略的`.local-literature-cache/`，记录用途；正式需要的原图和证据先移入本批正式目录并核验，再清理缓存。仅被忽略不代表可删除。
- 清理须有明确路径、无证据引用、保留正式替代或可重建来源的依据；逐文件核对哈希和边界，禁止`git clean/reset`、粗暴递归删除和批量改写原始资料。
- 小修改更新已有入口；不重复生成整库副本、全量压缩备份、长交接或一次性脚本。必须新增的交付清单应能解释用途，缓存与失败响应在收尾处理。

## 已核实但不能混淆的事情

2026-10-19只读核对D:/文献：1590个文件中1248个能在已提交项目文件或ZIP中找到同SHA256内容，覆盖全部401个PDF文件（含副本与SI）、XML、Word和原图；342个整理文件尚无逐字节相同的仓库副本，包含217 JSON、123 Markdown、2 HTML。所需137个LFS对象当时均返回可下载。本结论是内容备份核对，不是外部目录已经完整镜像；后续新增文件须重查。

用户指出原文只在ZIP中、路径分散会影响调用。完整可直接读取的文献入口与外部目录辅助文件镜像仍未实施；本次工作区整理没有擅自复制1.8 GB外部文献库或改变归档。后续应基于内容哈希与相对路径改进，避免不必要重复存储。

早期交付manifest可能同时记录公共README和知识入口在封版时的哈希。公共入口后续经Git审查更新不等于旧科学载荷损坏；应按提交解释差异，原始outputs、原文和数据库仍须核验，不重写历史manifest来掩盖变化。
